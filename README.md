# mememe — React + JSON API

A simple white-and-gray to-do app with two React components (App and TodoList),
an Express API, and a JSON file on the server. The API is the source of task data.

## Run locally

Use Node.js 22.12 or newer. From this project folder:

```sh
npm install
```

Keep two terminals open:

**Terminal 1 — backend:**

```sh
npm run server
```

The API listens on http://127.0.0.1:3001. It creates `server/data/tasks.json`
automatically on first start. This directory is ignored by Git.

**Terminal 2 — React frontend:**

```sh
npm run dev
```

Open the URL Vite prints (normally http://127.0.0.1:5173).
`vite.config.js` proxies `/api` to the backend, so no CORS setup is needed.
If Vite chooses another frontend port, the API proxy still works.

To check the production frontend, keep the backend running and use:

```sh
npm run build
npm run preview
```

To run the automated API/storage tests:

```sh
npm test
```

Tests use temporary files and an automatically allocated port, not your task data.

## Features and saving

- Add with the Add button or Enter; task text is trimmed and limited to 200 characters.
- Search and All / Completed / Uncompleted filters are combined on the server.
- Search requests wait 200 ms after typing. Obsolete requests are canceled.
- Edit with Save/Enter; Cancel/Escape discards the draft without changing the server.
- Completion and Low / Medium / High priority changes are saved immediately.
- Delete removes one task. Clear all removes **all** tasks, including hidden tasks.
- Tasks remain after refresh, closing the browser, and restarting the backend.
- Loading, saving, server errors, and Retry are shown in the UI. Failed mutations
  keep the input/edit draft; the UI never claims a failed change was saved.
- Typing a new task or editing its draft does not create/update a record until Add/Save.

The previous localStorage data is left untouched but is no longer read or updated.
It is not automatically imported. The new server starts empty unless its JSON file
already contains tasks. Browsers using this same backend share the server's tasks.

## API

All responses, including failures, are JSON. POST and PATCH require
`Content-Type: application/json`. The maximum request body is 16 KB.

| Method | Path | Purpose / JSON body |
| --- | --- | --- |
| GET | `/api/tasks` | Read all tasks and global counts |
| GET | `/api/tasks?search=react&status=Completed` | Combined case-insensitive search and status filter |
| POST | `/api/tasks` | Add: `{"text":"Learn React","priority":"High"}` |
| PATCH | `/api/tasks/:id` | Save edits or updates: `{"text":"Review React"}`, `{"completed":true}`, `{"priority":"Low"}`, or a combination |
| DELETE | `/api/tasks/:id` | Delete one task |
| DELETE | `/api/tasks` | Delete all tasks, regardless of UI filters |

Search is optional (max 200 characters). Status is `All` (default), `Completed`,
or `Uncompleted`. Unknown status values and repeated search/status parameters
are rejected. POST requires text; completed defaults to false and priority to Medium.
PATCH accepts one or more of text/completed/priority. Unknown fields are rejected.
IDs are generated by the server and cannot be changed.

GET example response:

```json
{
  "tasks": [
    { "id": "server-generated-id", "text": "Learn React", "completed": false, "priority": "High" }
  ],
  "summary": { "total": 1, "completed": 0, "remaining": 1 }
}
```

The summary counts **all** tasks, even when the returned tasks are filtered.
POST returns `201` and `{"task":{...}}`; PATCH returns `200` with the updated task.
Delete-one returns `{"deletedId":"..."}`; delete-all returns `{"deletedCount":3}`.
Errors use `{"error":"Message"}` with HTTP 400 (invalid input/JSON), 404 (missing
record/route), 405 (unsupported method), 413 (oversized body), 415 (wrong content type),
or 500 (storage failure).

Example with PowerShell:

```powershell
Invoke-RestMethod -Method Post -Uri http://127.0.0.1:3001/api/tasks `
  -ContentType 'application/json' -Body '{"text":"Learn React","priority":"High"}'
Invoke-RestMethod -Uri 'http://127.0.0.1:3001/api/tasks?search=react&status=Uncompleted'
```

## File storage and limits

The server queues mutations, writes a complete temporary JSON file, flushes it,
then renames it over the saved file. Memory is updated only after that succeeds.
Invalid existing JSON stops startup rather than silently erasing data. Back up the
JSON file; atomic writes are not a replacement for backups.

Run **one backend process per data file**. Do not edit the file while the backend
runs. This small local app has no authentication, database, cross-process locking,
or automatic live synchronization between browser tabs. Reload or change a search
filter to fetch other clients' changes. Concurrent edits to the same field use the
last accepted write. It is intended for local use and binds to loopback only.

Optional backend environment variables:

- `PORT`: defaults to 3001. If changed, update the target in `vite.config.js` too.
- `DATA_FILE`: optional JSON file path; relative paths use the working directory.

## Files

- `src/App.jsx`: page layout and heading.
- `src/TodoList.jsx`: React task UI and async actions.
- `src/api.js`: fetch and error handling.
- `src/styles.css`: simple styling.
- `server/index.js`: backend startup and configuration.
- `server/app.js`: API routes and validation.
- `server/store.js`: JSON loading and serialized atomic writes.
- `server/app.test.js`: API, restart, concurrency, validation and disk-failure tests.
- `vite.config.js`: frontend API proxy for development and preview.
